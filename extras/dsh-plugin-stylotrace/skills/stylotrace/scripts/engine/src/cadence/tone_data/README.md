# 字音表（tone_data）

## 为什么这里默认是空的

规格里写死了一条准确性红线：

> 字音表**不可由代码生成，也不可由 LLM 生成**。必须来自可核查的韵书数据源，
> 并在 README 里写明版本、来源、字数、许可。

所以本仓库**不附带**任何字音表。缺表时 CADENCE 的行为是：

- **结构层照常判定**（句数、每句字数、体式是五绝/七绝/五律/七律）——这部分不依赖字音表，是真实计算；
- **平仄层不做判定**：每个字标 `unknown`，`tonal_score` 返回 `null`，
  并在报告的 `notes` 里说明原因；
- **绝不猜**：多音字无法确定时同样标 `unknown` 并列出候选。

这比"编一个看起来很专业的分数"更符合工程纪律。

## 放什么文件进来

`pingshui.json`（平水韵）/ `xinyun.json`（中华新韵）/ `mandarin.json`（现代普通话）。

格式：

```json
{
  "source": "数据来源（书名/版本/URL）",
  "license": "许可",
  "note": "可选的补充说明",
  "chars": {
    "风": "平",
    "月": "仄",
    "重": ["平", "仄"]
  }
}
```

- `chars` 的值是 `"平"` 或 `"仄"`；
- **多音字用数组**表示（如 `"重": ["平","仄"]`）——代码会把无法确定的字标为 `unknown` 并列出候选，而不是替你选一个。

## 已知可用的数据来源（需自行核对许可）

- **Unihan 数据库**（Unicode 官方）：`kMandarin` 等字段给出现代普通话读音，
  可用于生成 `mandarin.json`（现代普通话声调 → 阴平/阳平为平、上声/去声为仄）。
- **平水韵**：需查可核查的韵书数据源。**中古入声字在普通话中派入四声**，
  所以平水韵 ≠ 普通话声调，不能用普通话表冒充。

放入真实数据后请把 `source` / `license` / 字数填全——报告会把它一并显示出来，
评审追问"数据从哪来"时能当场回答。

## 测试怎么办

测试不依赖真实韵书：`agent/test/cadence-meter.test.mjs` 用内存里的**测试夹具**验证
规则引擎（句式、孤平、三平调、粘对、多音字 unknown）是否正确，
并断言"缺表时必须老老实实返回 unknown"。夹具不是韵书，不会混进产物。
